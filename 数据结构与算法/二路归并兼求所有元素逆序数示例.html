严格按照伪代码执行示例（左右各3个元素）

为了极其严格地对照伪代码，先明确伪代码的变量含义和细节。

前置约定与伪代码细读：

  1. i 和 j 是原数组的全局索引。左半区间为 [l, m]，右半区间为 [m+1, r]。i 从 l 开始，j 从 m+1 开始。
  2. count 数组按原索引对应。
  3. 左半区间 a[l..m] 已经是升序排列的，右半区间 a[m+1..r] 也是升序排列的。
  4. 伪代码第5行 while i <= m or j <= r do：只要左、右还有元素，就继续循环。
  5. 第6行 if j > r or (i <= m and a_i <= a_j)：
    • 只要右半区空了，或者左边没空且 a_i <= a_j，就走 if 分支（即取出左半区元素）。
    • 第10行 count[i] ← count[i] + count[i-1]：前提是 i <= m。只有在出队左半区元素时（且它不是左半区的第一个元素），才把前一个左半区元素的计数累加给自己。
  6. 第12行 else：即 a_i > a_j（此时必定有 i <= m 且 j <= r），走 else 分支（取出右半区元素）。
    • 第14行 count[i] ← count[i] + 1：注意！这里的 i 是当前左半区未出队的第一个元素的索引。也就是说，右侧较小的元素 a_j，导致左半区当前指针 i 及其后面所有未出队的元素都增加 1 个逆序对。伪代码采用“延迟计算”，先全记在当前的 a_i 头上。

示例 （混合情况，严格按伪代码执行）

初始数组 a：[4, 6, 8, 2, 5, 7]

  • 左半边：l = 0, m = 2，元素为 a[0]=4, a[1]=6, a[2]=8
  • 右半边：m+1 = 3, r = 5，元素为 a[3]=2, a[4]=5, a[5]=7
  • 辅助数组 t 长度为 6。
  • 初始 count 数组：[0, 0, 0, 0, 0, 0]

初始化（伪代码第1~3行）：

  • i = l = 0
  • j = m + 1 = 3
  • k = l = 0

第 1 次循环

  • 执行前：i = 0, j = 3, k = 0
  • 第5行：i(0) <= 2 或 j(3) <= 5，满足条件，进入循环。
  • 第6行：判断 if (j > r) or (i <= m and a[i] <= a[j])。
    • j=3 > 5 为假。
    • i=0 <= 2 为真，且 a[0]=4 <= a[3]=2 为假。
    • 整体为假，进入 else 分支。
  • 第13行：t[0] = a[3] = 2
  • 第14行：count[0] = count[0] + 1。修改的是 count[0]。
    • count 变为：[1, 0, 0, 0, 0, 0]
  • 第15行：j = 3 + 1 = 4
  • 第17行：k = 0 + 1 = 1
  • 执行后：i = 0, j = 4, k = 1。t 数组前 1 个元素为 [2]。

第 2 次循环

  • 执行前：i = 0, j = 4, k = 1
  • 第5行：满足。
  • 第6行：判断 if。
    • j=4 > 5 为假。
    • i=0 <= 2 为真，且 a[0]=4 <= a[4]=5 为真。
    • 整体为真，进入 if 分支。
  • 第7行：t[1] = a[0] = 4
  • 第8行：i = 0 + 1 = 1
  • 第9行：if (i <= m)。此时 i=1 <= 2 为真，进入。
  • 第10行：count[1] = count[1] + count[0]。修改的是 count[1]。
    • count[1] = 0 + 1 = 1。
    • count 变为：[1, 1, 0, 0, 0, 0]
  • 第17行：k = 1 + 1 = 2
  • 执行后：i = 1, j = 4, k = 2。t 数组前 2 个元素为 [2, 4]。

第 3 次循环

  • 执行前：i = 1, j = 4, k = 2
  • 第5行：满足。
  • 第6行：判断 if。
    • i=1 <= 2 且 a[1]=6 <= a[4]=5 为假。
    • 进入 else 分支。
  • 第13行：t[2] = a[4] = 5
  • 第14行：count[1] = count[1] + 1。修改的是 count[1]。
    • count[1] = 1 + 1 = 2。
    • count 变为：[1, 2, 0, 0, 0, 0]
  • 第15行：j = 4 + 1 = 5
  • 第17行：k = 2 + 1 = 3
  • 执行后：i = 1, j = 5, k = 3。t 数组前 3 个元素为 [2, 4, 5]。

第 4 次循环

  • 执行前：i = 1, j = 5, k = 3
  • 第5行：满足。
  • 第6行：判断 if。
    • i=1 <= 2 且 a[1]=6 <= a[5]=7 为真。
    • 进入 if 分支。
  • 第7行：t[3] = a[1] = 6
  • 第8行：i = 1 + 1 = 2
  • 第9行：i=2 <= 2 为真。
  • 第10行：count[2] = count[2] + count[1]。修改的是 count[2]。
    • count[2] = 0 + 2 = 2。
    • count 变为：[1, 2, 2, 0, 0, 0]
  • 第17行：k = 3 + 1 = 4
  • 执行后：i = 2, j = 5, k = 4。t 数组前 4 个元素为 [2, 4, 5, 6]。

第 5 次循环

  • 执行前：i = 2, j = 5, k = 4
  • 第5行：满足。
  • 第6行：判断 if。
    • i=2 <= 2 且 a[2]=8 <= a[5]=7 为假。
    • 进入 else 分支。
  • 第13行：t[4] = a[5] = 7
  • 第14行：count[2] = count[2] + 1。修改的是 count[2]。
    • count[2] = 2 + 1 = 3。
    • count 变为：[1, 2, 3, 0, 0, 0]
  • 第15行：j = 5 + 1 = 6
  • 第17行：k = 4 + 1 = 5
  • 执行后：i = 2, j = 6, k = 5。t 数组前 5 个元素为 [2, 4, 5, 6, 7]。

第 6 次循环

  • 执行前：i = 2, j = 6, k = 5
  • 第5行：i(2) <= 2 满足。
  • 第6行：判断 if。
    • j=6 > 5 为真。
    • 进入 if 分支。
  • 第7行：t[5] = a[2] = 8
  • 第8行：i = 2 + 1 = 3
  • 第9行：i=3 <= 2 为假。不进入。
  • 第17行：k = 5 + 1 = 6
  • 执行后：i = 3, j = 6, k = 6。t 数组为 [2, 4, 5, 6, 7, 8]。

退出循环及收尾

  • 第5行：i(3) <= 2 假，j(6) <= 5 假。不满足，退出循环。
  • 第19-21行：将 t 复制回 a。
    • a 变为：[2, 4, 5, 6, 7, 8]
    • count 最终状态：[1, 2, 3, 0, 0, 0]

示例 结果验证与严格剖析

  • 4（原下标 0）：右侧比它小的只有 2。最终 count[0] = 1。（正确）
  • 6（原下标 1）：右侧比它小的有 2, 5。最终 count[1] = 2。（正确）
  • 8（原下标 2）：右侧比它小的有 2, 5, 7。最终 count[2] = 3。（正确）

严格对应伪代码的修改点总结：

步骤 操作 修改的 count 索引 修改逻辑的意义
第1次循环 else 分支（出右元素） count[0] 元素 2 比左半区当前未出队的 4 小，记为 4 的贡献。
第2次循环 if 分支（出左元素） count[1] 元素 4 出队，把它的贡献传给下一个左半区元素 6。
第3次循环 else 分支（出右元素） count[1] 元素 5 比左半区当前未出队的 6 小，记为 6 的贡献（此时 count[1] 累加变成了 2）。
第4次循环 if 分支（出左元素） count[2] 元素 6 出队，把它的贡献传给下一个左半区元素 8。
第5次循环 else 分支（出右元素） count[2] 元素 7 比左半区当前未出队的 8 小，记为 8 的贡献（此时 count[2] 累加变成了 3）。
第6次循环 if 分支（出左元素） 无 元素 8 出队，但因为它是左半区最后一个（i=3 > m=2），触发第9行的 if i <= m 拦截，不再传递。

核心结论

这版伪代码极其巧妙。第14行在右半区元素出队时，把逆序数记在左半区当前队列首部（即 i 指向的元素）头上；而第10行在左半区元素出队时，把队列首部的计数交给下一个元素。这种通过“队列指针平移”来传递计数的做法，完美避免了遍历更新，实现了 O(n) 的合并效率。

总之，这段伪代码是一种“延迟计算”的手法。在处理跨区间的逆序对时，利用左半区间有序的特性，右侧小元素的贡献统一先记在左半边最靠前的未出列元素头上（第14行），随后通过前缀和（第10行）如多米诺骨牌般往下传递，不仅省去了额外变量，还避免了对左半边所有剩余元素循环更新的O(n2) 操作，极其优雅且高效。
